# План развития SmartInput

Дата: 2026-09-05

## Цель

Безопасно сохранить и исследовать восстановленный локальный rule-pack Caramba,
сохранив самостоятельную архитектуру SmartInput, текущую
пунктуацию, двойной Shift, безопасные контексты и отсутствие передачи текста
пользователя в сеть.

## Этапы

### 0. Зафиксировать рабочую базу

- Сохранить текущие регрессионные тесты для раскладки, автокоррекции,
  пунктуации, отмены и Safe Mode.
- Собирать Release без подключения непроверенных бинарных правил.
- Не запускать тяжёлые корпусные аудиты на каждом изменении.

### 1. Защищённый контейнер модели CSM1

- [x] Реализовать чтение заголовка с проверкой magic, версии и лимитов.
- [x] Отдельно выделять AAD-заголовок, ciphertext+tag и подпись.
- [x] Проверять Ed25519-подпись до расшифровки.
- [x] Расшифровывать ChaCha20-Poly1305 с AAD-заголовком.
- [x] Распаковывать Zstandard с ограничением размера.
- [x] Проверять SHA-256, версию и атомарный rollback.
- Добавить writer только для CI/серверной сборки.

### 2. Репозиторий локальной модели

- [x] Ввести ModelRepository, который отдаёт только последнюю проверенную модель.
- [x] Добавить режим audit-only: rule-pack отдаёт только opaque ID и сырые
  записи, но не меняет текст и не принимает решений.
- Не хранить в логах слова, кандидаты и содержимое модели пользователя.

### 3. Адаптер Caramba-лексиконов

- [x] Реализовать безопасное чтение и bounds-checked переходы двух DAWG-блоков.
- [x] Реализовать bounds-checked output-link (`0x100`) → opaque `outputId`.
- [x] Загружать оба автомата, auxiliary-блок и все JSONL-таблицы с проверкой
  SHA-256 из manifest и package hashes.
- [x] Добавить offline-проверку точного соответствия reachable output ID и
  opaque raw records.
- [x] Повторить подтверждённые forward/reverse substring loops с restart на
  каждом байтовом смещении/окончании.
- [x] Воспроизвести подтверждённую часть boundary helper: известный UTF-8
  trim и выбор opaque callback branch.
- [x] Хранить версию rule-pack как audit-метаданные.
- [x] Добавить exact KBM `prepared bytes → outputId → text pool` provider в
  режиме audit/preview без live-применения.
- [x] Проверять хэш DAWG, границы pool, дубликаты ID и полный диапазон
  `0..70006` для переданной модели.
- [x] Прогнать все 70 007 canonical witness-ключей handoff-пакета.
- [x] Добавить privacy-safe shadow comparison KBM-кандидата с текущим
  `IPortableCorrectionEngine`.
- [x] Добавить single-owner gate с режимами `Disabled/AuditOnly/Preview/
  AllowList/Live` без изменения текущего live-пути.
- Восстановить оставшийся preprocessor data-flow (callback output, A/B runtime
  binding) и цепочку `outputId → rule → решение` на синтетических примерах.
- Подключать сначала только ручные suggestions после доказательства этой
  цепочки; автоматическую замену не планировать до отдельного review.

Текущий анализ блоков остаётся audit-only: совпадение пути в DAWG ещё не
считается словом. Контрольный запуск по локальным RU/EN-лексиконам показал,
что простое предположение о терминальном бите и порядке букв не даёт
достаточного покрытия; поэтому этот бит и принадлежность блоков пока не
включены в рабочий движок.

### 4. Обновление движка исправлений

- Сохранить физическое преобразование клавиш SmartInput.
- Использовать модель для словарного подтверждения и языковых весов.
- Сохранять консервативный Wait при неоднозначности.
- Оставить ручную конвертацию и двойной Shift независимыми от модели.

### 5. Пунктуация

- Сохранить отдельный локальный модуль пунктуации SmartInput.
- [x] Добавить чистый `PunctuationProvider → manual preview` контракт с
  обратимой картой вставок; default provider ничего не меняет.
- [x] Добавить локальный rule-based baseline и отдельную страницу
  «Проверка пунктуации» с явным применением только внутри окна и отменой.
- [x] Зафиксировать исследование готовых локальных моделей и план ONNX-
  подключения в `docs/PUNCTUATION_PROVIDER_RESEARCH_RU.md`.
- Не назначать три Shift: двойной Shift остаётся мгновенной отменой.
- Расширять только после отдельных тестов на URL, email, код, числа и аббревиатуры.
- Не смешивать пунктуационные правила с DAWG-кандидатами.

### 6. Trial-лицензия

- Реализовать 7-дневный UTC trial через Windows DPAPI.
- Блокировать только автоматическую раскладку и автокоррекцию после окончания.
- Не удалять модель, словари, настройки или пользовательские правила.
- Добавить активацию подписанным токеном и экран статуса лицензии.

### 7. Интерфейс и обновления

- Показать источник активной модели и её версию.
- Добавить статус проверки модели без технических деталей для пользователя.
- Добавить безопасное обновление и rollback.

### 8. Отложено

- Голосовой ввод.
- Облачная проверка больших текстов через нейросеть.
- Любая отправка введённого текста на сервер без отдельного согласия.

## Критерии готовности

- Все существующие тесты проходят.
- Модель не меняет текст в Safe Mode, secure input, URL, email, путях и коде.
- Повреждённый контейнер не загружается.
- Ошибка обновления сохраняет последнюю рабочую модель.
- Пунктуация работает независимо от trial и DAWG.
- Ни один диагностический журнал не содержит пользовательский текст.
