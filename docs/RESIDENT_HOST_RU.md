# Лёгкий фоновый режим SmartInput

## Зачем он нужен

Обычное приложение объединяло в одном процессе две очень разные вещи: окно
настроек на Avalonia и постоянно работающий перехват клавиатуры. Окно — самая
тяжёлая часть. Новый `SmartInput.ResidentHost` оставляет в памяти только
коррекционный движок, системный трей, глобальные клавиши и нативные оверлеи.

Окно настроек запускается отдельно только при выборе «Настройки» из трея и
закрывается как обычное окно. Оба процесса используют один локальный файл
настроек. После сохранения в окне фоновый процесс подхватывает изменение; текст
пользователя ни в файл, ни в журналы не попадает.

## Что уже сохранено

- Автоматическая раскладка, орфография, пунктуация и шаблоны используют тот же
  runtime, что и обычное приложение.
- Double Shift, ручное исправление, защита полей, Safe Mode и исключённые
  приложения не меняются.
- Трей позволяет включать и выключать существующие функции, поставить
  экстренную паузу, открыть настройки или завершить фоновый процесс.
- Словари остаются локальными и поставляются в компактном `sidict`-формате.

## Текущий замер

На этой машине Release-процесс был запущен в простое на 8 секунд и затем
остановлен. Результат: **84.1 МБ рабочей памяти Windows** и **49.3 МБ private
memory**. Это не обещание одинаковой цифры на каждом компьютере: Windows,
антивирус, драйверы ввода и версия .NET меняют рабочий набор. Но это уже вместо
примерно 180–210 МБ обычного оконного процесса.

Цель 30–40 МБ private memory остаётся ориентиром. Следующие честные источники
экономии — отключаемые в простое prediction/overlay-компоненты и выпускной
анализ зависимостей. Урезать правила исправления или защиту ради красивой цифры
нельзя.

Когда предсказания выключены, resident host не создаёт их движок, нативный
оверлей и связанные таймеры. При включении предсказаний в настройках они
инициализируются безопасно без перезапуска. Если предсказания были включены уже
при старте, их компоненты, разумеется, остаются загруженными.

## Как запустить для проверки

1. Закройте обычный `SmartInput.exe`, чтобы не было двух глобальных перехватов.
2. Соберите оба Release-проекта.
3. Перед запуском задайте путь к оконной части через `SMARTINPUT_UI_EXE`.
   В инсталляторе оба EXE будут лежать рядом, поэтому переменная не потребуется.
4. Запустите `SmartInput.ResidentHost.exe`. Значок SmartInput появится в трее.

Для разработки из текущей папки PowerShell-команда выглядит так:

```powershell
$env:SMARTINPUT_UI_EXE = "C:\Users\shuly\Desktop\Автоматический Т9 на комп\src\SmartInput.App\bin\Release\net8.0-windows\win-x64\SmartInput.exe"
& "C:\Users\shuly\Desktop\Автоматический Т9 на комп\src\SmartInput.ResidentHost\bin\x64\Release\net8.0-windows\win-x64\SmartInput.ResidentHost.exe"
```

Нажатие «Настройки» в трее откроет UI-only окно без второго перехвата клавиш.
При выборе «Выйти» останавливается именно фоновый процесс.

## Ограничение этого этапа

Это рабочий новый режим, но пока он не является запуском по умолчанию и не
устанавливается вместе с приложением одним пакетом. Перед переключением на него
по умолчанию нужны отдельная проверка реального ввода и сборка установщика,
кладущая оба EXE в одну папку.
