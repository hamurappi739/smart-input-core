# Техническое и дизайнерское ТЗ для сайта Smart Input

## Готовая задача для AI-разработчика сайта

Ты разрабатываешь красивый презентационный сайт для Smart Input — локального
Windows-приложения, которое помогает печатать на русском и английском без
раздражающих ошибок раскладки и опечаток.

Исходный код продукта находится в публичном репозитории:

<https://github.com/hamurappi739/smart-input-core>

Сначала изучи `README.md`, `ARCHITECTURE.md`, `PRIVACY_ARCHITECTURE.md`,
`SAFETY_LAYER.md`, исходники `src/SmartInput.Core` и тесты. Не выдумывай
функции, которых нет в репозитории. Сайт должен объяснять существующий
продукт и показывать синтетические интерактивные демонстрации его логики.

## Что такое Smart Input

Smart Input — полностью локальный помощник для Windows 10/11. Он анализирует
ввод на компьютере и помогает в трёх основных ситуациях:

1. Пользователь печатает слово в неправильной раскладке.
2. Пользователь допускает обычную орфографическую опечатку.
3. Пользователь хочет сохранить свой вариант, шаблон или вручную отменить
   последнее исправление.

Основной принцип продукта: исправлять уверенно, сомнительное оставлять как
есть. URL, email, пути, код, бренды, модели и аббревиатуры не должны случайно
портиться.

Движок работает офлайн. Пользовательский текст не отправляется в облако.
В текущей архитектуре C# Core владеет live replacement, а Rust scorer
подключён как audit/shadow-компонент для безопасного сравнения.

## Главная идея сайта

Посетитель должен за первые 10 секунд понять:

> Smart Input замечает неправильную раскладку и опечатки прямо во время
> печати — локально, быстро и без ручного перепечатывания всего слова.

Сайт должен не просто рассказывать о продукте, а дать посетителю поиграть с
ним через живые мини-демонстрации.

## Структура страницы

### 1. Hero-блок

Заголовок — короткий и сильный:

> Печатай как думаешь. Smart Input исправит остальное.

Подзаголовок:

> Локальный помощник для Windows, который исправляет раскладку и опечатки
> прямо во время печати — без облака и лишних действий.

В hero размести интерактивную клавиатуру или строку ввода. При нажатии на
кнопку «Показать пример» должна проигрываться последовательность:

```text
ghbdtn  →  привет
руддщ   →  hello
```

Анимация должна показывать физические клавиши, короткую задержку анализа,
замену токена и появление следующего пробела. Не изображай мгновенную
магическую замену без этапа принятия решения.

Кнопки:

- «Посмотреть, как это работает» — прокрутка к playground.
- «Открыть репозиторий» — ссылка на GitHub.

### 2. Интерактивный playground

Это центральный блок сайта. Сделай его похожим на небольшое окно Smart Input,
но визуально более презентационным.

В playground должны быть вкладки или переключатели:

- «Раскладка»;
- «Опечатка»;
- «Двойной Shift»;
- «Защита».

#### Демо раннего распознавания раскладки

Покажи строку:

```text
п р и в е т
```

При вводе первых символов или на четвёртом символе покажи timeline:

```text
1 2 3 4 5 6
      ↑ уверенный сигнал раскладки
```

Затем анимируй преобразование неправильного физического ввода в правильный
вариант. Подпиши, что раннее решение является консервативным: система не
переключает язык по одному случайному символу.

Используй реальные демонстрационные пары:

```text
ghbdtn       → привет
руддщ        → hello
стрвнно      → странно
кмнда        → команда
здраствуйте  → здравствуйте
```

#### Демо орфографии

Сделай карточку «Одно слово вместо перепечатывания»:

```text
кмнда       → команда
стрвнно     → странно
здраствуйте → здравствуйте
```

Покажи, что движок выбирает кандидат только при достаточной уверенности.
Добавь индикатор confidence, но не показывай его как псевдонаучную точность:
это визуальное объяснение внутреннего решения, а не обещание 100% качества.

#### Демо Double Shift

Покажи два состояния:

```text
пзе  →  gpt
```

Подпись:

> Двойной Shift — явная команда пользователя. Она работает даже для
> коротких слов, которых нет в обычном словаре.

После повторного двойного Shift покажи Undo:

```text
gpt  →  пзе
```

Отдельно покажи автоматическое исправление и отмену последней замены. Важно:
не смешивать Double Shift с нейронной моделью — это детерминированная команда
ядра и адаптера клавиатуры.

#### Демо консервативной защиты

Покажи две колонки:

```text
Исправит уверенно                 Оставит без изменений
ghbdtn → привет                   https://example.com/ghbdtn
кмнда  → команда                   user@example.com
руддщ  → hello                    C:\\Temp\\ghbdtn.txt
                                  gemini / BMW / AAA / GPT / A4
```

Подпись:

> Если токен похож на код, бренд, модель, URL, email или путь — лучше ничего
> не менять.

Покажи короткие слова отдельно:

```text
ыру → she
рук → her только в английском контексте
рук → рук в обычном русском контексте
```

Это демонстрирует, что движок учитывает контекст и не ломает настоящее
русское слово.

### 3. Блок экономии времени

Сделай интерактивное сравнение двух сценариев.

Слева — ручной путь:

```text
заметил ошибку → остановился → выделил слово → удалил → сменил раскладку
→ перепечатал → вернулся к фразе
```

Справа — Smart Input:

```text
печатал дальше → система проверила границу слова → заменила только токен
→ пробел доставлен один раз → пользователь продолжил фразу
```

Добавь счётчик «10 слов» и анимируй набор фразы. Пользователь может менять
количество слов и время ручной коррекции. Расчёт должен быть явно помечен как
иллюстративный сценарий, а не как лабораторный benchmark:

```text
ручной сценарий: количество слов × время одной ручной коррекции
Smart Input: короткая проверка границы + одна автоматическая замена
экономия: разница между двумя сценариями
```

Не публикуй выдуманные проценты и не называй оценку измерением. Если нужны
реальные цифры, показывай только цифры из репозитория и подписывай источник.

### 4. Как это работает

Покажи понятную горизонтальную схему из шести шагов:

```text
Ввод с клавиатуры
      ↓
Буфер текущего слова
      ↓
Преобразование физической раскладки
      ↓
Словарь + частотность + морфология
      ↓
Safety gate и confidence
      ↓
Точная замена токена и доставка границы
```

Под схемой объясни простым языком:

- раскладка — детерминированное соответствие физических клавиш;
- словарь — проверка известных слов и форм;
- морфология — поддержка словоформ;
- контекст — помощь в неоднозначных коротких словах;
- safety gate — финальное решение «исправить или оставить»;
- boundary handling — пробел или знак препинания доставляется ровно один раз.

Не описывай Smart Input как обычный онлайн-переводчик. `ghbdtn → привет` —
это восстановление раскладки, а не машинный перевод.

### 5. Offline и privacy

Сделай отдельный блок доверия:

- работает локально;
- не требует постоянного интернета;
- пользовательский текст не нужен облачному API;
- защищённые контексты не исправляются;
- диагностические данные — агрегированные, без сырого текста;
- Rust shadow-путь не выполняет live replacement.

Визуально используй локальную схему «клавиатура → компьютер пользователя»,
без облака и серверных стрелок.

### 6. Инженерная надёжность

Покажи компактные proof-карточки без преувеличений:

- Core regression: 1726/1726;
- App tests: 155/155;
- ResidentHost tests: 5/5;
- privacy audit: 0 unsafe logger findings;
- Rust scorer: audit/shadow, live replacement не перехватывает.

Рядом добавь подпись:

> Это результаты текущего локального аудита репозитория, а не универсальная
> гарантия одинакового поведения во всех приложениях Windows.

Не показывай в интерфейсе сайта пользовательские логи, реальные пути Windows,
заголовки окон, email или сырые диагностические события.

## Визуальный стиль

Нужен дорогой, современный, технологичный сайт — не шаблонная страница
очередного SaaS.

Рекомендации:

- фон: графитовый или почти чёрный;
- основной текст: тёплый светлый;
- акцент: лаймовый, янтарный, коралловый или фиолетовый;
- не делать весь дизайн электрически-синим;
- панели — полупрозрачные, с тонкой рамкой и мягким свечением;
- клавиши — объёмные, с коротким press-анимационным эффектом;
- переход темы — плавное распространение цвета по блокам и строкам, как
  аккуратная волна, но без раздражающего мерцания;
- анимации должны иметь `prefers-reduced-motion` режим;
- не использовать бесконечные фоновые видео и тяжёлые 3D-сцены.

Визуальный язык должен объединять три идеи: клавиатура, исправление и
локальная безопасность. Можно использовать мотив двух направленных стрелок,
но не копировать стандартную иконку перевода.

## UX-требования

- Посетитель должен понять продукт без чтения длинного текста.
- Каждая анимация должна объяснять конкретную функцию.
- Демонстрации должны иметь кнопки pause/replay.
- В каждой интерактивной секции должна быть короткая подпись «что произошло».
- На мобильном экране сначала показывать результат, затем подробности.
- Все элементы управления должны быть доступны с клавиатуры.
- Контраст текста и фона должен соответствовать WCAG AA.
- Не использовать терминологию `KMB`, `FFI`, `FST`, `shadow` и `ABI` в первом
  экране. Технические детали можно вынести в раздел «Для разработчиков».

## Технические ограничения для сайта

- Создай сайт в отдельной папке `website/` и не ломай существующие C#,
  Windows и Core-проекты.
- Все demo-сценарии должны работать на клиенте и не отправлять введённые
  строки на внешний сервер.
- Используй только синтетические примеры из этого ТЗ.
- Не подключай live keyboard hook из desktop-приложения к сайту.
- Не выдавай demo-анимацию за реальное вмешательство в клавиатуру браузера.
- Добавь `README` с запуском, сборкой и описанием demo-сценариев.
- Добавь тесты для основных интерактивных состояний.
- Добавь поддержку тёмной темы и reduced motion.
- Не копируй в сайт локальные настройки пользователя, user dictionary,
  crash-dumps, `bin/obj`, логи или старые review-пакеты.

## Готовая формулировка позиционирования

Smart Input — локальный Windows-помощник, который превращает неправильную
раскладку и частые опечатки в нормальный текст прямо во время печати. Он
понимает разницу между случайной ошибкой, настоящим словом и защищённым
техническим токеном, поэтому исправляет уверенные случаи и оставляет
сомнительные без изменений.

## Варианты коротких слоганов

- Печатай как думаешь.
- Нормальный текст — с первого раза.
- Неправильная раскладка больше не ломает мысль.
- Исправляет текст, не мешая печатать.
- Локальный умный ввод без лишнего шума.

## Elevator pitch

Smart Input — локальный помощник для Windows, который замечает неправильную
раскладку и опечатки во время печати. Он исправляет уверенные случаи, учитывает
контекст коротких слов, защищает URL и код, а пользователь всегда может
отменить последнее изменение двойным Shift.

## Чего нельзя обещать на сайте

- «100% правильные исправления»;
- «нейросеть понимает абсолютно любой текст»;
- «замена происходит во всех приложениях Windows без ограничений»;
- «Rust уже владеет live replacement»;
- «приложение экономит конкретно N минут каждому пользователю», если это не
  подтверждено отдельным измерением;
- «ввод пользователя анализируется в облаке».

Сайт должен продавать ощущение спокойной и быстрой печати, но сохранять
инженерную честность продукта.
