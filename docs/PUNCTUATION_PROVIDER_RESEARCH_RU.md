# Исследование готовых решений для локальной пунктуации

Дата проверки: 2026-09-05

## Вывод

Готовые модели есть, но ни одна не является безусловно безопасной заменой
SmartInput: модели восстановления пунктуации обучались главным образом на
ASR-транскриптах и возвращают вероятностные метки. Поэтому их следует
подключать к существующему `PunctuationProvider` только через ручной preview,
жёсткие safety-фильтры и одну Undo-транзакцию.

## Кандидаты

### RUPunct_small ONNX

[Карточка модели RUPunct_small ONNX](https://huggingface.co/ekhodzitsky/rupunct-small-onnx)
указывает MIT-лицензию, INT8 ONNX и token-classification для русской
пунктуации/регистра. Модель принимает текст без знаков и предсказывает метку
после токена. Это наиболее подходящий кандидат для будущего офлайн-provider,
потому что ONNX Runtime запускается локально и не требует Python во время
работы.

Проверить до поставки:

- точные входные/выходные имена ONNX и tokenizer vocabulary;
- классы знаков и соответствие индексов меткам;
- F1 отдельно для запятой, точки и вопросительного знака на нашем корпусе;
- размер модели в памяти и p50/p95 задержку на CPU;
- поведение на разговорной речи, сленге, коде и смешанном тексте;
- лицензионные файлы всех зависимостей tokenizer/model.

### ru-autopunctuation

[Репозиторий kotikkonstantin/ru-autopunctuation](https://github.com/kotikkonstantin/ru-autopunctuation)
содержит BERT-подход для восстановления точки, запятой и вопросительного
знака. README показывает ASR-ориентированный pipeline и веб-сервис. Его можно
использовать как источник идей, датасета и baseline, но сетевой Flask-сервис
нельзя вызывать из keyboard hook; для SmartInput нужен локальный inference.

### ru_punct

[Репозиторий gleb-skobinsky/ru_punct](https://github.com/gleb-skobinsky/ru_punct)
описывает BRNN-модель для точки, запятой и вопросительного знака и приводит
раздельные precision/recall. Автор предупреждает о доменной зависимости от
новостного корпуса, поэтому эти цифры нельзя переносить на любой пользовательский
текст без собственного benchmark.

### BERT token-classification baseline

[markusiko/rubert-base-punctuation](https://huggingface.co/markusiko/rubert-base-punctuation)
предсказывает знак после каждого слова на базе ruBERT. Это полезный
исследовательский baseline, но его необходимо оборачивать в локальный tokenizer,
ограничение окна и safety policy. Генеративные rewrite-модели для фоновой
автозамены не подходят: они могут менять слова и форматирование, а не только
знаки.

## Что уже реализовано в SmartInput

- чистый `IPunctuationProvider` без доступа к окну процесса и input API;
- консервативный `RuleBasedPunctuationProvider` для ручного preview;
- `PunctuationPreviewService` с лимитом длины, запретом URL/email/path/code,
  чисел и mixed-script;
- результат содержит только структурированные предложения знаков и обратимую
  карту вставок;
- preview можно явно применить только в окне и отменить кнопкой «Отменить»;
- глобальный hook и автоматическая замена слов этим провайдером не затрагиваются.

## План подключения ONNX-модели

1. Положить модель и tokenizer в подписанный локальный CSM1-пакет.
2. Проверить SHA-256/подпись до загрузки и ограничить размер.
3. Загружать `InferenceSession` один раз вне hook; запросы выполнять
   последовательно и отменять устаревший preview.
4. Преобразовать только метки пунктуации в `PunctuationProposal`.
5. Отклонять низкую уверенность, конфликтующие метки и небезопасный контекст.
6. Сравнить модель с rule-baseline на отложенном корпусе.
7. Оставить модель ручным preview до прохождения precision/safety/Undo gates.

Три Shift для этого пути не используются: двойной Shift уже занят мгновенной
отменой существующих коррекций.
