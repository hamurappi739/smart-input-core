# Запрос к независимой нейросети: исследование DAWG Caramba

## Контекст

В проект SmartInput передан восстановленный пакет CarambaSwitcher:

```text
C:\Users\shuly\Desktop\CarambaSwitcher-Recovery-Package-2026-09-05\
```

В пакете есть распакованная модель `model\latest-rules-decoded.bin` и два
извлечённых блока `integration\dawg\lexicon-a.dawg` и
`integration\dawg\lexicon-b.dawg`.

Подтверждено:

1. блок начинается с `u32 little-endian` — количеством записей;
2. затем идут записи `u32`;
3. переход вычисляется так:

```text
base = (records[state] >> 10) << (8 if records[state] & 0x200 else 0)
candidate = state XOR label_byte XOR base
```

Переход действителен, если:

```text
0 <= candidate < records.Length
AND (records[candidate] & 0x800000FF) == label_byte
```

Не подтверждено: terminal flag, порядок букв, принадлежность блоков RU/EN и
то, являются ли блоки словарями или индексами/признаками.

## Задача

Проведи независимое исследование бинарных DAWG-блоков. Не ограничивайся
предположением, что `0x100` — это terminal flag. Все гипотезы проверь
экспериментально и отделяй доказанные факты от предположений.

### 1. Проверка формата

- перепроверь размер и количество записей обоих блоков;
- перепроверь root state `0` и формулу перехода;
- проверь отсутствие выходов за границы и циклов;
- укажи достижимые состояния, рёбра и максимальную глубину.

### 2. Поиск терминального признака

Проверь `0x100`, `0x200`, `0x400`, `0x800`, `0x1000`, `0x2000`, `0x4000`,
`0x8000`, `0x80000000`, их комбинации, low byte, high bit и соседние записи.
Проверь признак на текущем и следующем состоянии, прямой и обратный порядок
букв, UTF-8 и однобайтные label-последовательности.

Для каждой гипотезы посчитай только агрегаты: достигнутые контрольные слова,
принятые слова, precision/recall RU и EN, ложные срабатывания, короткие и
длинные слова. Полные списки слов не записывай; отдельные примеры замени
хэшированным `caseId`.

### 3. Определение RU/EN-блока

Используй локальные словари:

```text
src\SmartInput.Core\Dictionaries\Lexicons\ru_50k.csv
src\SmartInput.Core\Dictionaries\Lexicons\en_50k.txt
```

Минимальный набор:

```text
RU: привет, жизнь, машина, команда, начало, дать, меняй
EN: hello, world, machine, command, start, receive, the
```

Проверь пары раскладки:

```text
ghbdtn ↔ привет
руддщ ↔ hello
gtie ↔ пишу
```

Если прямое прохождение даёт низкое покрытие, проверь граф как индекс
префиксов/суффиксов, граф обратных строк, байтовые токены или признаки
автокоррекции. Низкое покрытие само по себе не доказывает бесполезность.

### 4. Сопоставление с исходным EXE

Если возможно, статически проанализируй
`binaries\CarambaSwitcherPro.exe`: найди функцию проверки слова, отследи
чтение записи после последней буквы и сравнения с флагами.

Не запускай непроверенную функцию через keyboard hook и не подключай её к
автоматической замене.

## Формат ответа

```text
| Гипотеза | Блок | Порядок | Покрытие RU | Покрытие EN | Ложные срабатывания | Статус |
```

После таблицы дай: наиболее вероятное объяснение формата; точный terminal
predicate, если он доказан; доказательство принадлежности блоков RU/EN;
оставшиеся неизвестные; минимальный безопасный API для `audit-only`; тесты для
SmartInput; прямой ответ, можно ли подключать блоки к автоматической замене.

## Ограничения

- не менять production-код SmartInput;
- не подключать DAWG к keyboard hook;
- не принимать случайное совпадение пути за слово;
- не удалять Safe Mode, защиту URL/email/кода и правило `Wait`;
- не писать пользовательский текст, слова ввода или кандидатов в логи;
- при недостатке доказательств прямо написать «не доказано».
